# Learning Log: FastAPI + Celery + RabbitMQ Skeleton

## Date: 2026-08-18
## Session: End-to-end skeleton (API publishes, Worker executes)

---

### Q: How does a task flow from HTTP request to execution?

**The journey of `test_task`:**

1. **User hits endpoint:** `curl -X POST "http://localhost:8000/test-publish?message=hello"`
2. **main.py receives request:** The `test_publish` function runs
3. **main.py calls `test_task.delay(message)`:** This SERIALIZES the task (name + arguments + task_id) into a message
4. **Celery publishes to RabbitMQ:** The message goes to the default `celery` queue
5. **RabbitMQ holds the message:** Waits for a consumer (worker) to pick it up
6. **Worker receives message:** RabbitMQ pushes it over the open connection
7. **Worker deserializes:** Reads task name (`app.celery_app.test_task`), finds the Python function
8. **Worker executes:** Calls `test_task("hello")` — this is where "Received message: hello" prints
9. **Worker sends ack:** Tells RabbitMQ "done, remove the message"
10. **Result stored:** Worker returns `"Processed: hello"` (stored in result backend if configured)

### Q: What files does the message pass through?

**Publishing path (API container):**
- `app/main.py` — FastAPI endpoint, calls `test_task.delay()`
- `app/celery_app.py` — Celery app instance, task definition
- `app/config.py` — RABBITMQ_URL (where to publish)

**Message queue:**
- RabbitMQ — holds message in `celery` queue

**Consuming path (Worker container):**
- `app/celery_app.py` — Celery app loads, registers `test_task`, connects to RabbitMQ
- `app/config.py` — RABBITMQ_URL (where to connect)
- Worker receives message, finds `test_task` by name, executes it

### Q: What is the task_id in the message?

`2fc13aa0-4def-4103-a4be-97a189e0f257` — a UUID generated by Celery when `.delay()` is called. Used to track task state and results. We'll use this later for idempotency tracking.

### Q: What does "received" mean in worker logs?

`Task app.celery_app.test_task[...] received` — RabbitMQ delivered the message to the worker. The worker deserialized it, identified the task function, and is about to execute it. NOT the same as "executed" — received means "picked up from queue."

### Q: What does "succeeded" mean?

The task function ran without raising an exception and returned a value. Celery marked it successful. The worker then sends ack to RabbitMQ to remove the message.

## Bug Fixed: os.getenv vs config import

**Symptom:** Worker trying to connect to `127.0.0.1:5672` instead of `rabbitmq:5672`

**Root cause:** `celery_app.py` had:
```python
app = Celery("oncall_investigator", broker=os.getenv("RABBITMQ_URL"))

RABBITMQ_URL is NOT an env var — it's built in config.py from components. os.getenv("RABBITMQ_URL") returned None, so Celery used its default broker (localhost).

Fix:

python
from app import config
app = Celery("oncall_investigator", broker=config.RABBITMQ_URL)
```

Lesson: os.getenv() reads environment variables. config.RABBITMQ_URL is a Python value built in config.py. Don't confuse the two. If you build URLs in config.py, import and use them directly — don't wrap in os.getenv().

# Learning Log: SQLAlchemy Models & Database Layer

## Date: 2026-08-20
## Session: Postgres integration (models, db.py, FastAPI startup)

---

### Q: What is SQLAlchemy?
**A:** An ORM (Object Relational Mapper) for Python. Instead of writing raw SQL strings, you define tables as Python classes and query them with Python code. Postgres is the database; SQLAlchemy is the bridge.

### Q: Why use UUID as primary key?
**A:** UUIDs can be generated in application code (before DB insert), which means the API can publish to RabbitMQ with the ID before the DB insert commits. Auto-increment IDs require the DB to generate them — creating a dependency on DB write completing first. UUIDs also work well in distributed systems (no central coordination).

### Q: What's the difference between ForeignKey and relationship()?
**A:** 
- `ForeignKey` = actual DB constraint. Creates the FK column in Postgres.
- `relationship()` = Python-level convenience. NOT stored in DB. Just a shortcut to fetch related rows.
- Example: `inv.steps` automatically queries `investigation_steps WHERE investigation_id = X`

### Q: What does back_populates do?
**A:** Links two relationship() properties so both directions work:
- `inv.steps` → all steps for an investigation
- `step.investigation` → the investigation a step belongs to
Without back_populates, setting one side doesn't update the other.

### Q: What is FastAPI's Depends(get_db)?
**A:** Dependency injection — similar to Spring's @Autowired but function-level. When an endpoint has `db: Session = Depends(get_db)`, FastAPI calls get_db() before the function runs and passes the result. Each request gets its own DB session (connection).

### Q: create_tables() on startup vs Alembic?
**A:** create_tables() creates tables if they don't exist — fine for MVP with locked schema. Alembic is for production — versioned migrations for evolving schemas. In interview: "Schema is fixed for v1, so create_tables() is sufficient. I'd introduce Alembic if the schema needed to evolve."

### Q: Is create_tables() in main.py production-grade?
**A:** Not really. It's acceptable for portfolio/MVP. Production uses migration tools. Defensible answer: "The design is locked, no schema changes planned. Alembic would be overengineering for this scope."
